# Vanilla+ Mailboxes

A Fabric mod for Minecraft 26.3 that adds a wooden mailbox block. It sits on top of fences and walls, works like a small chest, and opens with an animated door and flag.

## Features

- Placed on fences and walls. Breaks when the support is removed, and drops its contents.
- 5-slot storage with a hopper-style menu.
- Hitbox and model follow the mailbox shape.
- 12 wood types for the body, 9 door materials (diamond, gold, iron, netherite, and copper that oxidizes, plus waxed versions).
- Oxidation, waxing with honeycomb (shift + right-click), and scraping with an axe (shift + right-click), all like vanilla copper.
- Door and flag animations driven by `mailbox_animation.json`. Reversing mid-swing is smooth.
- Redstone: the mailbox powers the fence or wall below it, and that signal reaches nearby dust and blocks while it holds items.
- Servers without the mod are handled gracefully. The client blocks mailbox items and shows a message instead of disconnecting.

## Requirements

- Minecraft 26.3
- Fabric Loader 0.20.1 or newer
- Fabric API 0.166.2+26.3 or newer

Install on the server and on every client that joins it. Clients that join a server without the mod see a message and can't use mailboxes there.

## Building

Requires JDK 25.

```
cd "Fabric mod"
./gradlew build
```

The jar appears in `Fabric mod/build/libs/`.

## Releases

Publishing a GitHub release builds the jar automatically (`.github/workflows/release.yml`) and attaches it to the release. The release name sets the version and must look like:

- `v1.0.0 (Minecraft 26.3)`
- `v1.0.0-beta4 (Minecraft 26.3)`

The Minecraft version in the name must match `minecraft_version` in `Fabric mod/gradle.properties`, or the build fails. The attached jar is named `VanillaPlusMailboxes-fabric-mc26.3-<version>.jar`.

To test the build without publishing a release, run the "Build release jar" workflow manually from the Actions tab and enter a release name. The jar is then available as a workflow artifact.

## Repository layout

- `Fabric mod/`: the Fabric mod (Java source, resources, Gradle build).
  - `src/main/java/com/burgertown/mailbox/`: block, block entity, networking, and client rendering code.
  - `src/main/resources/`: models, blockstates, recipes, sounds, textures, and animations.
  - `scripts/generate-variants.ps1`: regenerates the per-wood and per-metal files (see below).
- `Blockbench/`: Blockbench project files (`mail_box.bbmodel`, `mailbox.ajblueprint`) and the exported models in `Blockbench/Exports/`, including the hitbox (`mailbox_hitbox.json`) and animation (`mailbox_animation.json`).
- `Textures/`: the flag texture (16×16, includes the rivet).
- `Sounds/`: the custom open and close sounds.
- `Modrinth/`: the promo image for the Modrinth page.

`Minecraft assets/` isn't part of the repo. It holds Mojang's textures and sounds, which can't be redistributed. The mod loads the vanilla planks and metal blocks from the game at runtime.

## Generated files

The per-wood body models, blockstates, item models, loot tables, recipes, language file, and axe tag for all 144 variants are generated by `Fabric mod/scripts/generate-variants.ps1`. Run it from PowerShell after changing the body model or the variant list:

```
powershell -ExecutionPolicy Bypass -File "Fabric mod\scripts\generate-variants.ps1"
```

It reads `Blockbench/Exports/mailbox_body.json`, so re-export the body there before running it.
